# Приёмка MVP

Критерии §14.2 спецификации и тесты, которые их проверяют. Все тесты запускаются на стенде `dataguard-dev` и проходят на дату 03.11.2026.

| № | Критерий | Чем проверено | Результат |
|---|---|---|---|
| 1 | Агент подключается к PostgreSQL и MySQL с минимальными привилегиями | `TestScannerAccountCannotChangeData` — учётная запись сканера на всех 4 СУБД читает, но не может `UPDATE`, `DELETE`, `CREATE` | Выполнен |
| 2 | Находит email, телефоны, ИНН | `TestDiscoveryOnEveryEngine` на 4 СУБД; корпус классификатора, precision и recall 1,0 на 350 решениях, включая случайные числа с верной контрольной суммой | Выполнен |
| 3 | Не сохраняет исходные значения в центре, логах и очередях | Поиск всех реальных значений из таблиц в журналах агента и сервера, в расшифрованной очереди, в PostgreSQL и ClickHouse (`TestPlatformEndToEnd`), а также в перехваченном трафике агент→центр (`TestDiscoveryOnEveryEngine`). Негативный контроль подтвердил, что поиск срабатывает | Выполнен |
| 4 | Определяет столбцы в SELECT, JOIN, подзапросах | `TestResolverCorpus`: 20 типов запросов × 3 диалекта, включая CTE, UNION, представления и `*` | Выполнен |
| 5 | Фиксирует успешные и неуспешные обращения | `TestAuditOnEveryEngine` | PostgreSQL, MariaDB, SQL Server — да. MySQL Community — нет, журнал не содержит исхода (ограничение СУБД, показано в возможностях) |
| 6 | Отличает техническую учётную запись от подтверждённой личности | `TestApplicationContext`: подпись проверена, подделка не попадает в событие, контекст не переходит в следующую транзакцию | Выполнен (только PostgreSQL) |
| 7 | Показывает неизвестную личность | `IDENTITY_CONFIDENCE_UNKNOWN`, в интерфейсе «Не идентифицирован»; проверено в браузере | Выполнен |
| 8 | Показывает потерю событий и периоды без аудита | Юнит-тесты сборщика: ротация, усечение, переполнение очереди, неразбираемые строки, заблокированные события. Покрытие различает «нет активности» и «нет наблюдения» | Выполнен |
| 9 | Переживает отключение центрального сервера | `kill -9` сервера и агента в `TestPlatformEndToEnd`; отключение центра в `TestCenterOutageLosesNothingAndDuplicatesNothing` — ни потерь, ни дублей | Выполнен |
| 10 | Не создаёт критической нагрузки на БД | `TestScanStaysWithinBudgetAndBarelyTouchesLatency`: бюджет строк и скорости соблюдается, p95 точечного запроса 362 → 382 мкс во время скана | Выполнен |

## Уровни тестов

| Уровень | Команда |
|---|---|
| Юнит, линтер, уязвимости | `make check` |
| Интеграция на стенде | `make test-integration` |
| Реальные бинарники и Keycloak | `make test-e2e` |
| Нагрузка | `make test-performance` |
| Браузер | См. README, раздел «Разработка» |

## Что найдено при приёмке и исправлено

- CSP блокировал вход: источник с путём совпадает только с точным путём.
- Проверка аудита SQL Server сообщала «не настроено» при работающем аудите: каталог аудита не виден сканеру.
- Ограничитель скорости позволял вдвое превысить бюджет в первую секунду.
- Сборщик SQL Server при первом запуске вставал на 5000-ю запись журнала вместо конца и повторно доставлял записи с общим смещением под новыми ID.
- Фильтр служебных запросов скрывал вызовы функций и чтение системных таблиц, включая `mysql.user`.
- Переполнение удерживаемых сессий PostgreSQL отбрасывало запись без учёта потери.
