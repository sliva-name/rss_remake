# ADR-0002. Закрытый контракт исходящих сообщений

Статус: принято.

## Контекст

§9.1 предлагает цепочку Schema Validator → Sensitive Field Scanner → Allowlist → Sanitizer. Сканер значений ненадёжен: он пропустит то, чего не знает, а санитайзер маскирует ошибку в коде, который сформировал сообщение.

## Решение

Каждое строковое и байтовое поле protobuf-контракта объявляет `FieldKind`. Guard проверяет значение по виду и блокирует сообщение целиком.

Тест на дескрипторах обходит все запросы агента и падает на поле без вида, на `map` и на открытых типах (`Struct`, `Any`).

## Почему не JSON

В JSON-контракте произвольное поле появляется незаметно. Здесь список разрешённого выводится из схемы и проверяется при сборке.

## Последствия

- Добавить поле дороже: нужно выбрать вид. Это намеренно.
- Вид `IDENTIFIER` пропускает любой текст до 128 символов без управляющих. Сам по себе он значение не отличит, поэтому имена в событиях обязаны идти из каталога (ADR будет дополнен на этапе 3).
