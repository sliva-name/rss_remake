# ADR-0006. Источники создаются в центре, пароль запечатан ключом агента

Статус: принято. Заменяет ADR-0003.

## Контекст

Центр задуман как единая точка управления: источники, сканирование, политики, отчёты. В ADR-0003 источники и пароли жили в файле агента. Новую базу приходилось добавлять правкой конфигурации на сервере заказчика. Требование ADR-0003 остаётся: взломанный центр не должен получать пароли и не должен направлять агента куда угодно.

## Решение

1. **Источник создаётся в центре.** Его описание: имя, агент, СУБД, адрес, порт, база, пользователь, режим TLS, каталог журналов аудита, лимит соединений. Центр отдаёт агенту список его источников по `GetSources`.
2. **Список подписан ключом политик** с отдельным префиксом, чтобы подпись политики нельзя было выдать за подпись списка. Список адресован арендатору и агенту, его версия только растёт. Агент сохраняет принятый список и работает по нему, пока центр недоступен.
3. **Пароль запечатан ключом агента.** При регистрации агент создаёт ключ ECDH P-256, отдельный от ключа mTLS. Открытую часть он передаёт центру. Браузер шифрует пароль этим ключом: эфемерный ECDH, HKDF-SHA256, AES-256-GCM. Шифротекст привязан к арендатору, агенту, СУБД, адресу, порту, базе, пользователю и режиму TLS. Центр хранит только шифротекст и расшифровать его не может. Если центр поменяет адрес у существующего источника, агент не расшифрует пароль.
4. **Агент принимает только цели из локального списка разрешённых.** Список обязателен и задаётся при установке: сети в нотации CIDR, отдельные адреса и имена хостов, в том числе по маске `*.домен`. Для журналов аудита — каталоги. Источник вне списка агент не открывает и сообщает центру код `TARGET_NOT_ALLOWED` или `AUDIT_DIRECTORY_NOT_ALLOWED`.
5. **Позиция чтения журнала привязана к `source_id`,** а не к имени. Переименование источника не сбрасывает сбор.
6. **Удаление источника мягкое.** История инвентаря и событий остаётся, агент закрывает подключение.

## Последствия

- Источник добавляется и меняется в интерфейсе. Файл агента сокращается до адреса центра, каталога состояния и списка разрешённых целей.
- Остаточный риск: интерфейс раздаёт центр. Активно взломанный центр может подменить страницу и перехватить пароль в момент ввода. Защищены пароли, введённые до взлома, утечка базы или резервной копии центра и пассивный доступ к нему.
- Взломанный центр может направить агента к разрешённому хосту с режимом TLS `disable`. Пароль, запечатанный для другого режима, агент не расшифрует. Но центр может назначить такой источник с паролем, который знает сам.
- Каталог аудита SQL Server — путь на сервере СУБД, его читает функция `sys.fn_get_audit_file`. Локальный список каталогов к нему не применяется.
- Источник обслуживает один агент. При перерегистрации агента пароли вводятся заново.
- Расписания сканирования в этом решении нет: скан запускается из интерфейса.
