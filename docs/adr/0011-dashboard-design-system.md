# ADR-0011. Дизайн-система Dashboard на Tailwind и готовых компонентах

Статус: принято. Требование владельца от 08.11.2026: использовать готовые фреймворки вместо самописных, полный редизайн интерфейса.

## Контекст

Dashboard был написан на одном файле CSS и пяти общих функциях. Каждая таблица, кнопка и форма собиралась заново, поэтому одинаковые элементы выглядели и вели себя по-разному:
- подтверждения шли через `window.confirm`;
- не было иконок, боковых панелей, графиков, настройки колонок и выбора строк.

Разделы повторяли друг друга: покрытие аудита показывалось в двух местах, «Отчёты» дублировали «Каталог».

## Решение

1. **Стили — Tailwind CSS 4.** Цвета задаются один раз токенами в `web/dashboard/src/tokens.css` и подключаются к утилитам через `@theme`. Светлая и тёмная темы — один набор классов: тема меняет значения токенов, а не классы. Тема входа Keycloak берёт копию тех же токенов, тест `theme.test.ts` следит, чтобы копия не разошлась.
2. **Компоненты с поведением — Radix (`radix-ui`).** Диалоги, боковые панели, меню, подсказки, вкладки, уведомления и выпадающие списки. Radix даёт фокус, клавиатуру и ARIA, оформление остаётся нашим. Писать это заново — значит повторить чужие ошибки доступности. Родной `<select>` не используется: его варианты нельзя оформить, поэтому `Select` из `ui/form.tsx` показывает вариант с подсказкой и отметкой выбранного в том же стиле, что и меню.
   - Масштаб — для чтения, а не для плотности: основной текст 15 px, поля и кнопки 36 px, ячейки таблиц с отступом 14 px по вертикали, страница с полями 32 px. Плотный режим таблиц остаётся выбором пользователя.
   - Строка таблицы занимает одну-две линии и помещается в экран 1440 px без горизонтальной прокрутки. Длинные списки в ячейке сокращаются: категории — первые и «+N» с подсказкой; связанные значения сводятся в одну ячейку (имя таблицы и её база › схема, тип события и исход, чувствительных колонок «из» всех). Редкие колонки скрыты по умолчанию и включаются в настройке колонок.
3. **Таблицы — TanStack Table 9.** Один компонент `DataTable` для всех списков, набор возможностей таблицы объявлен в нём один раз, страницы описывают колонки типом `TableColumn`:
   - настраиваемые колонки и плотность, выбор хранится у пользователя в браузере;
   - сортировка — только там, где загружен весь список;
   - выбор строк с массовыми действиями;
   - серверная пагинация, пустое, загрузочное и ошибочное состояния.

   Сортировка одной страницы серверного списка вводила бы в заблуждение, поэтому для таких списков её нет.
4. **Графики — Recharts 3.** Оси, подсказки и адаптивный контейнер. Цвета рядов проверены на различимость при нарушениях цветовосприятия для обеих тем. Recharts грузится только со страницей обзора: каждая страница — отдельный чанк.
5. **Иконки — lucide-react**, классы собираются через `clsx` и `tailwind-merge`.
6. **Версии закреплены точно** и обновляются до последних выпусков (требование владельца от 08.11.2026; прежнее правило о двух неделях с выпуска снято).
7. **Визуальный язык** (требование владельца от 08.11.2026: «сделать красивее»):
   - **Шрифты — Inter и JetBrains Mono** из `@fontsource-variable`. Они собираются вместе с Dashboard, потому что он может работать там, где внешние адреса недоступны. Табличные цифры включены только там, где числа выравниваются в столбец: числовые колонки, время, счётчики. В Inter эта функция расширяет и дефис, и имена вида `crm-main` распадались бы на части. Страница входа Keycloak шрифтов не грузит и остаётся на системном.
   - **Акцент — индиго**, нейтральные цвета чуть холоднее. Боковое меню тёмное в обеих темах, у него свои токены `--nav-*`: оно обрамляет рабочую область и не теряется на светлой странице.
   - **Глубина — тонкая рамка и мягкая тень**, без тяжёлых рамок. Карточки скруглены на 12 px. Разделитель под заголовком панели есть только над таблицей или списком.
   - **Категории — нейтральная метка с цветной точкой группы**: персональные, государственные, финансовые, аутентификация, медицинские, собственные (`--cat-*`). Цвет предупреждения остаётся за состояниями, иначе строка из категорий читается как тревога.
   - У раздела в заголовке страницы его иконка, как в меню. У плиток показателей — иконка рядом с числом. Период выбирается сегментированным переключателем.

## Информационная архитектура

Разделы сгруппированы по задачам (ADR-0010):

| Группа | Раздел | Что внутри |
|---|---|---|
| — | Обзор | Состояние сбора, активность, что требует внимания, что читают, изменения |
| Данные | Инвентаризация | Источники → таблицы, поиск по пути «база.схема.таблица», фильтр чувствительных |
| Данные | Классификация | Категории (хранение и обращения вместе), находки, детекторы |
| Аудит | Журнал событий | Фильтры в адресе, боковая панель события со ссылками на объекты |
| Аудит | Пользователи СУБД | Кто обращался, с фильтром по категории |
| Аудит | Сигналы риска | Всплески чтений и отказов, новые категории для пользователя, с правилами расчёта |
| Инфраструктура | Источники | Список, покрытие аудита, возможности, сканирования |
| Инфраструктура | Агенты | Состояние связи, подключение агента |
| Контроль | Политика | Собственные детекторы и бюджет скана, публикация |
| Администрирование | Среды, Организации | |

Разделов без функций нет: «Расследования» и «Пользователи и роли» появятся вместе с функциями. Избранное и сохранённые представления — в разделе «Личное» бокового меню (ADR-0010). Прежние адреса (`/catalog`, `/access`, `/identities`, `/compliance`, `/infrastructure`) перенаправляют на новые с сохранением фильтров.

## Последствия

- Новая страница собирается из готовых компонентов и выглядит как остальные без отдельной работы.
- Зависимостей стало больше: `radix-ui`, `@tanstack/react-table`, `recharts`, `lucide-react`, `clsx`, `tailwind-merge`, а для сборки `tailwindcss` и `@tailwindcss/vite`. Главный чанк — около 560 КБ, 170 КБ в gzip; Recharts — в чанке обзора.
- Для сценариев редизайна бэкенд получил только необязательные параметры и новые операции чтения: поиск, временной ряд, фильтры таблиц, «кто читал колонку», период истории. Существующие контракты не изменились.
