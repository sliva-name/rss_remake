# Спецификация коннекторов

Коннектор — адаптер, который переводит особенности СУБД в общие типы. Он работает только у агента.

## Принципы

- Возможности раздельные. Коннектор реализует только то, что умеет его СУБД.
- Отсутствующая функциональность не имитируется. Источник сообщает `SUPPORT_UNAVAILABLE`.
- Неудачная проверка возможности даёт `SUPPORT_UNKNOWN`, но никогда не `AVAILABLE`.
- Значения проходят только через `ColumnProfiler` и не покидают его как значения.

## Матрица MVP

| | PostgreSQL | MySQL Community | MariaDB | SQL Server |
|---|---|---|---|---|
| Discovery и профилирование | Да | Да | Да | Да |
| Механизм аудита | pgAudit + `jsonlog` | `general_log` | `server_audit` | `sys.fn_get_audit_file` |
| Аудит чтения | Да | Да | Да | Да |
| Статус выполнения | Да | **Нет** | Да | Да |
| `returned_rows` | Нет | Нет | Нет | Нет |
| Контекст приложения | Да | Нет | Нет | Нет |
| Сэмплирование | `TABLESAMPLE` | Ограниченный префикс | Ограниченный префикс | `TABLESAMPLE` |
| Доступ к журналу | Файл | Файл | Файл | SQL |

Матрица отражает то, что проверяется интеграционными тестами. Детальные оговорки появляются здесь по мере реализации этапов 2 и 3.

## Требования к чтению данных

- Только транзакции read-only там, где СУБД это поддерживает.
- Обязательны таймаут запроса и таймаут блокировки.
- Соблюдаются лимиты `ScanBudget`: длительность, строки, байты, соединения, скорость.
- Идентификаторы берутся из каталога и экранируются средствами диалекта. Параметры подставляются только через bind.
- Значения читаются в переиспользуемый буфер, который очищается после пакета.
- Текст ошибок драйвера преобразуется в `safeerr` на границе коннектора.

## Добавление новой СУБД

1. Создать пакет в `internal/connector/`.
2. Реализовать нужные интерфейсы возможностей.
3. Добавить значение в `Engine` и сервис в `deployments/dev/compose.yml`.
4. Запустить общий набор контрактных тестов коннектора.
5. Обновить матрицу.

Ядро менять не требуется.
